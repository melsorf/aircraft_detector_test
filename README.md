Тесты собираются в двух режимах:
- BUILD_AIRCRAFT_DETECTOR=OFF - собирается библиотека детектора и юнит-тесты
- BUILD_AIRCRAFT_DETECTOR=ON - дополнительно собираются eCAL-адаптер и продуктовый бинарь aircraft_detector

Продуктовый бинарь собирается специально для интеграционных тестов. Тесты запускают его как отдельный процесс и взаимодействуют с ним через eCAL

Основная логика:

- detector.hpp:

Детектор получает точки, хранит состояние треков, рассчитывает скорость и определяет, является ли точка самолётом. Также он отслеживает таймауты и отправляет события об исчезнувших целях.
Логика детектора не зависит от eCAL, поэтому её можно отдельно проверять юнит-тестами

- detector_config.hpp

Загрузка и проверка конфигурации из config/detector.yaml - граничных параметров из задачи. Эти параметры используются и продуктом, и тестами при генерации тестовых значений

- ecal_adapter.*:

Связывает логику detector'a с транспортом eCAL. В юнит-тестах он не используется: вместо него детектор получает тестовый TestSink через интерфейс ITargetSink. Это позволяет тестировать логику детектора без запуска eCAL и реального обмена сообщениями.

- hlp_clock.hpp

Тестовые часы, используются в unit-тестах. Не используют реальное системное время: тест может вручную продвинуть TestClock на необходимый интервал.
Это позволяет проверять таймауты без реального ожидания

- hlp_sink.hpp

Тестовый получатель результатов детектора (тестовая реализация ITargetSink). Позволяет юнит-тестам проверять опубликованные TargetStatus и TargetLost без использования eCAL, подменяет EcalAdapter

- hlp_track.hpp

Общие структуры для представления тестовых траекторий и их обработки. Здесь также находится ScenarioGenerator - общий для unit- и интеграционных тестов генератор случайных тестовых траекторий.
Параметры генератора берутся из конфигурации детектора, фиксированный seed делает сценарии воспроизводимыми

- detector_test.cpp

Файл с unit-тестами. Проверяют непосредственно логику детектора. Они не запускают продуктовый бинарь и не используют eCAL. Вместо системных часов испольнуют TestClock и без ожидания двигают время на нужный интервал моментально. Вместо публикации результатов через eCAL - TestSink

- ecal_detector_test.cpp

Интеграционные тесты, проверядют взаимодействие компонентов через eCAL. Они запускают продуктовый бинарь aircraft_detector, отправляют ему RadarPoint через eCAL, ожидают TargetStatus\TargetLost и проверяют результат в соответствии со сценарием.

- ecal_test_bus.* - тестовая обертка над eCAL. Используется для отправки и получения сообщений между интеграционным тестом и продуктовым процессом.

- aircraft_detector_process.* - управляет жизненным циклом продуктового процесса.

- detector.yaml - конфигурационный файл, общий на тесты и на продукт. Из него без пересборки подтягиваются параметры скорости, количества точек и таймаута, упомянутые в условии.

- config.yaml - конфигурационный файл для запуска пайплайна с юнит-тестами.

- nightly.yaml - конфигурационный файл для запуска пайплайна с интеграционными тестами и пересборкой продукта. Выделен отдельно из-за scheduled-запуска вместо on-pr и on-push - такие тесты требуют гораздо большего времени на прогон, а при изменении продуктовых функций важно проверить, в первую очередь, правильность логики, а не eCAL-взаимодействия
